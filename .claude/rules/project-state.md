# Project state

**Where things stand (2026-09-30):** the whole API and schema (migrations 0001–0007) are built and tested locally (127 tests). The UI foundation, the login screen and the member payment screens exist; admin screens and member prepayments are placeholders / not built. Not started: the admin dashboard API, reminders. Not done: anything remote — no D1 created, no secret set, no deploy, no Cron Trigger declared. Next agreed step: UI, starting with login and the member payment screen (to scan a real VietQR early).

The scaffold exists: `package.json`, `wrangler.jsonc`, Vite + React + Tailwind client shell, a Hono Worker with one route (`GET /api/health` → 204). Envelope (`ok` / `failure` / `notFound` / `handleError`), `validate.ts`, `securityHeaders` and `public/_headers` exist; `/api/health` answers the envelope. Migrations `0001`–`0007` exist and are applied **locally only**. It was edited in place once (2026-09-29, email → username) while no remote database existed and the local one held no data; the local D1 was reset and re-migrated. **From the moment the remote D1 is created, applied migrations are never edited — no exceptions.** Auth exists (PBKDF2 at 10,000 iterations — not yet measured on a deployed Worker, JWT cookie, `requireAdmin` / `requireMember`, `/api/auth/*`, `scripts/hash-password.mjs`). `/api/accounts` exists (admin account management; `requireAdmin` re-reads the role from D1 each request). `/api/plans` exists (admin plan CRUD with payer and bank details), with plan seats (`/api/plans/:code/members`, `PATCH /api/members/:code`). Billing periods exist (`GET`/`POST /api/plans/:code/periods`, `scheduled()` → `createDuePeriods`); **no Cron Trigger is declared** in `wrangler.jsonc`. Member routes (`/api/me/*`: plans, payments, mark-sent, prepayments), admin payment and prepayment routes, and the in-house VietQR payload exist. UI foundation exists (tokens, fonts, `components/ui/`, i18next, `api.ts`, session, role router, layouts, confirm, toast, chunk error boundary); login, `/payments` and `/payments/:code` are built; admin screens are placeholders. Nothing is deployed, no D1 database has been created (`database_id` in `wrangler.jsonc` is an all-zero placeholder), and no Worker secret has been set.

Decided before any code exists (amended 2026-09-29: no automatic splitting — the admin sets the plan price and one per-member amount on the plan; each plan has a payer who is an ADMIN and has no seat):

- One Worker serves the SPA and `/api/*`; one D1 database. No Pages, no R2, no other bindings.
- Plain SQL against the D1 binding, kept in `src/server/db/` — no ORM.
- No receipt uploads. A member marks a payment as sent; an admin confirms it.
- Deployed to the same Cloudflare account as other Workers, so free-tier quotas are shared (see `platform-limits.md`).

`docs/roadmap.md` is the authoritative backlog.
